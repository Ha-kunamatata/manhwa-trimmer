# 만화경

만화를 만화책처럼 읽는 도구. 이름 그대로 **만화**를 보는 **경**(鏡)이다.

### → [ha-kunamatata.github.io/manhwa-trimmer](https://ha-kunamatata.github.io/manhwa-trimmer/)

설치할 것도, 로그인할 것도 없다. 브라우저 안에서만 동작하며 **이미지는 어디로도 전송되지 않는다.**

---

## 무엇을 하는 도구인가

**열면 서재가 나온다.** 폴더를 골라 만화책처럼 읽는 것이 이 앱의 본업이고,
자르는 일은 화당 한 번이라 헤더의 **이미지 자르기** 버튼 뒤에 있다.

| | |
|---|---|
| **뷰어** (첫 화면) | 폴더를 골라 진짜 만화책처럼 **읽는다** — 종이가 휘며 넘어가고, 핀·목차·확대·이어보기가 있다 |
| **편집** (헤더 버튼) | 길게 캡처한 세로로 긴 이미지를 만화책 판형에 맞춰 낱장으로 자르고 **저장한다** |

**뷰어는 자르지 않은 이미지도 읽는다.** 긴 캡처가 든 폴더를 고르면 편집과 똑같은 방식으로
페이지를 찾아 만화책처럼 보여준다. 저장할 게 아니라 그냥 읽고 싶을 뿐이라면 편집을 거칠 필요가 없다.

정리하면 이렇게 갈린다.

| 하고 싶은 것 | 어디로 |
|---|---|
| 그냥 **읽고 싶다** (자른 것이든 아니든) | 열면 바로 거기 |
| 잘라서 **파일로 남기고 싶다** | 헤더의 **이미지 자르기** |

---

# 사용법 1 — 편집 (자르기)

## 1. 이미지 올리기

헤더의 **이미지 자르기**를 누르고, 긴 캡처 이미지를 끌어다 놓거나 클릭해서 고른다.
PNG · JPG · WebP를 받는다. 한 번에 한 장씩 처리한다.

올리면 바로 분석이 시작된다. 큰 이미지는 몇 초 걸린다.

## 2. 알아서 잡은 것을 확인한다

분석이 끝나면 미리보기에 두 가지가 겹쳐 그려진다.

- **빗금 친 바깥 영역** — 잘라낼 사이트 UI (상하단 광고 배너, 좌우 여백)
- **가로선** — 페이지가 나뉘는 자리

왼쪽 패널에는 판단 근거가 적힌다. 예를 들면

> 한 페이지 배치로 판단했어요. 페이지 폭 580px × 1.414 → 9장, 경계 정확도 94%.

**대부분 여기서 끝난다.** 선이 여백 한가운데에 잘 떨어져 있으면 그냥 저장하면 된다.

## 3. 어긋났으면 손으로 고친다

| 증상 | 이렇게 한다 |
|---|---|
| 선 하나가 없거나 남는다 | 미리보기에서 **그 자리를 클릭**한다. 빈 곳을 누르면 선이 생기고, 기존 선 근처를 누르면 지워진다. 새 선은 가까운 여백 한가운데로 알아서 붙는다 |
| 전체가 한 장씩 밀렸다 | **페이지 수**를 ±1 한다 |
| 전체가 조금씩 위아래로 어긋난다 | **시작 보정**(px)을 조절한다. 첫 페이지가 시작하는 위치를 밀거나 당긴다 |
| 판형을 잘못 잡았다 | **만화책 판형**을 직접 고른다. 단행본(1:1.414) · 신서판(1:1.5) · 와이드판(1:1.3), 또는 비율 직접 입력 |
| 광고 배너가 덜 잘렸다 | **만화 영역**의 위/아래/왼쪽/오른쪽 값을 직접 고친다. **자동 재감지**로 되돌릴 수 있다 |

손으로 고친 게 있으면 **수동 편집 초기화** 버튼이 나타난다. 자동 판단으로 되돌리고 싶을 때 누른다.

> **판형을 직접 고르면 자동 맞춤이 꺼진다.** 자동이 잘 맞고 있다면 건드리지 않는 편이 낫다 —
> 자동은 후보를 실제 이미지에 대보고 채점해서 고르는 반면, 직접 고른 비율은 그냥 그 값으로 균등 분할한다.

## 4. 저장한다

세 가지 길이 있다.

**PDF 한 파일로 저장** (권장) — 전체가 한 파일로 나온다. 폰·태블릿의 아무 PDF 뷰어에서나 열린다.
용량이 크면 화질을 단계적으로 낮춰가며 자동으로 맞춘다.

**낱장 이미지로 저장** — 페이지마다 `이름_01.png`, `이름_02.png` … 로 나온다.
**뷰어로 다시 읽으려면 이쪽이다.** 브라우저가 "여러 파일 다운로드를 허용할까요?"라고 물으면 허용한다.

**개별 페이지 저장** — 페이지 카드의 ⤓ 아이콘. 한 장만 필요할 때.

파일 이름과 화질은 **내보내기** 패널에서 정한다. **고화질 PNG**를 끄면 JPEG로 나와 용량이 크게 준다.

**만화책으로 읽기**를 누르면 저장하지 않고 바로 읽어볼 수도 있다. 잘린 결과를 확인하는 데 좋다.

# 사용법 2 — 뷰어 (읽기)

뷰어가 읽는 것은 두 종류다. 폴더를 고르면 **첫 이미지를 한 번 열어보고 어느 쪽인지 스스로 판단한다.**

- **이미 잘라둔 낱장** — 그대로 한 장씩 넘긴다
- **아직 자르지 않은 긴 캡처** — 편집과 똑같은 판단으로 페이지를 찾아 넘긴다

## 1. 폴더를 이렇게 만들어 둔다

### 잘라둔 낱장이라면

뷰어는 폴더 이름으로 시리즈와 화를 알아본다. 규칙은 하나다 —
**페이지가 든 폴더가 화, 그 위 폴더가 시리즈.**

```
만화/                     ← 이 폴더를 고른다
  원피스/                 ← 시리즈
    001화/                ← 화
      p01.png             ← 페이지
      p02.png
    002화/
      p01.png
  나루토/
    001화/
      p01.png
```

폴더를 하나만 골라도 된다. 어느 층을 골라도 같은 규칙으로 읽는다.

| 고른 것 | 결과 |
|---|---|
| `만화/` | 시리즈 여러 개, 각각 화 여러 개 |
| `원피스/` | 시리즈 하나(원피스), 화 여러 개 |
| `001화/` | 화 하나 |

### 자르지 않은 긴 캡처라면

**긴 캡처 한 장이 곧 한 화다.** 그래서 계층이 한 단 올라간다 — 캡처를 담은 폴더가 시리즈,
캡처 파일 하나하나가 화가 된다. 화 폴더를 따로 만들 필요가 없다.

```
만화/                     ← 이 폴더를 고른다
  슬램덩크/               ← 시리즈
    001화.png             ← 화 하나 = 긴 캡처 한 장
    002화.png
  원피스/
    001화.png
```

화를 열면 그때 페이지를 찾는다 (한 화에 1~3초). **한 번 찾은 결과는 앱을 닫아도 남으므로**
다음에 열 때는 기다리지 않는다. 파일이 바뀌면 다시 잰다. 사이트 UI(광고 배너, 좌우 여백)는 편집과 똑같이 자동으로 제거된다.

> 한 화가 캡처 **여러 장**으로 나뉘어 있다면 그 장들이 각각 별개의 화로 잡힌다.
> 이어서 읽는 데는 문제가 없지만 목록이 잘게 나뉜다.

**파일 이름은 사람이 읽는 순서대로 정렬된다.** `9화`가 `10화`보다 앞에 오고,
`p2.png`가 `p10.png`보다 앞에 온다. 자릿수를 맞춰 `p01`, `p02`로 두면 더 확실하다.

## 2. 폴더를 고른다

**뷰어 → 폴더 선택.**

브라우저마다 사정이 다르다.

| | |
|---|---|
| **데스크톱 Chrome / Edge** | 폴더를 고르면 권한이 남는다. 다음에 열 때 **‹폴더이름› 다시 열기** 버튼 한 번이면 된다 |
| 그 외 데스크톱 브라우저 | 폴더를 고를 수는 있지만 매번 다시 골라야 한다 |
| **iOS Safari** | 폴더 선택 자체가 없다. **이미지 여러 개 선택**을 쓴다 (한 화씩 읽게 된다) |

## 3. 읽는다

시리즈 카드를 누르면 화 목록이 나오고, 화를 누르면 읽기가 시작된다.

- **한 화가 끝나면 다음 화로 이어진다.** 마지막 쪽에서 한 번 더 넘기면 된다
- **어디까지 읽었는지 표시된다.** 다 읽은 화에는 `✓`, 읽는 중인 화에는 진행 막대가 붙는다
- **이어 읽기** 버튼은 *아직 안 끝낸 첫 화*를 연다. 3화를 다시 들춰봤다고 해서
  다음에 3화로 데려가지 않는다
- **화 번호로 찾는다.** `12`를 치면 `012화`도 `12-13화`도 나온다
- **안 읽음 / 읽는 중 / 다 읽음**으로 걸러 볼 수 있다
- 시리즈 목록은 **읽고 있는 것이 앞**에 온다
- 기억은 이 기기의 브라우저에만 남는다 (기기 간 동기화는 아직 없다)

## 읽기 화면 조작

### 손가락 · 마우스

| | |
|---|---|
| 화면 좌우 끝을 누른다 | 페이지를 넘긴다 |
| **좌우로 끈다** | 종이가 손끝을 따라 휘며 넘어간다. 중간에 놓으면 되돌아가고, 튕기면 넘어간다 |
| **가운데를 누른다** | 위아래 막대가 사라져 페이지만 남는다. 다시 누르면 돌아온다 |
| 두 손가락으로 벌린다 | 확대 · 축소 |
| 더블 클릭 / 더블 탭 | 그 자리를 확대, 한 번 더 누르면 원래대로 |
| 확대한 채로 끈다 | 페이지를 움직인다 |
| 휠을 굴린다 | 페이지 넘김 (Ctrl과 함께 굴리면 확대) |

오른쪽→왼쪽으로 읽는 중이면 **왼쪽을 눌러야 다음 장**이다. 종이 만화책과 같다.

### 키보드

| | |
|---|---|
| `←` `→` | 페이지 넘기기 (읽는 방향에 따름) |
| `Space` / `PageDown` | 다음 |
| `PageUp` | 이전 |
| `Home` / `End` | 처음 / 끝 |
| `D` | 한 쪽 / 두 쪽 전환 |
| `P` | 이 페이지 핀 |
| `B` | 핀 목록 |
| `T` | 페이지 목록 |
| `F` | 전체화면 |
| `0` | 확대 원래대로 |
| `Esc` | 패널 닫기 → 뷰어 닫기 |

### 위쪽 버튼

| | |
|---|---|
| **깃발** | 지금 페이지를 핀한다 |
| **핀** | 핀한 페이지 목록. 눌러서 바로 이동하거나 뺀다 |
| **목차** | 페이지 썸네일 목록. 아무 페이지나 눌러 점프 |
| **설정** | 아래 보기 설정 |
| **전체화면** | 화면을 꽉 채운다 |

아래쪽 슬라이더를 끌면 화 안에서 빠르게 이동한다.

### 설정 안에 있는 것

| | |
|---|---|
| **한 쪽 / 두 쪽** | 낱장으로 볼지, 책처럼 펼쳐 볼지. 처음엔 화면 크기를 보고 알아서 정한다 |
| **표지 단독 / 나란히** | 첫 장을 표지로 혼자 둘지. 짝이 어긋나 보이면 이걸 누른다 |
| **읽는 방향** | 일본·한국 만화는 오른쪽→왼쪽, 서양 만화는 왼쪽→오른쪽 |
| **맞춤** | 한 화면에 다 넣을지, 가로를 꽉 채우고 세로로 스크롤할지 |
| **넘기는 모션** | 끄면 즉시 바뀐다 |
| **읽기 방식** | 책장 넘기기 / 이어서 스크롤 |
| **페이지 수** | 자동으로 자른 결과가 어긋났을 때 `−` `+`로 조절한다. 자르지 않은 긴 캡처를 읽을 때만 나온다 |

설정은 기억되므로 매번 다시 맞출 필요가 없다.

---

## 핀 — 다시 볼 페이지 표시해두기

읽다가 위쪽 **깃발**을 누르면 그 페이지가 핀된다. **핀** 버튼을 누르면 시리즈별로 모아 보여주고,
누르면 그 자리로 바로 간다 — **다른 화의 핀이면 그 화를 열어서** 간다.
기억은 이 기기에 남으므로 뷰어를 닫았다 열어도 그대로다.

> 핀은 폴더 이름과 파일 이름으로 기억한다. 그 폴더를 아직 고르지 않았다면 먼저 골라야 한다.

읽던 위치는 핀하지 않아도 **자동으로 기억한다.** 뷰어 맨 위에 `이어서 읽기` 칸이 뜨고,
누르면 마지막에 읽던 화의 그 페이지에서 이어진다.

> 폴더 권한이 남아 있는 브라우저(데스크톱 Chrome/Edge)에서는 폴더를 다시 고르지 않고 바로 이어진다.
> 그 외에서는 폴더를 한 번 다시 골라야 한다 — 브라우저가 폴더를 기억해주지 않기 때문이다.

## 이어서 스크롤 — 폰으로 읽을 때

**설정 → 읽기 방식**을 `이어서 스크롤`로 바꾸면 페이지가 세로로 이어진다.
책장을 넘기는 대신 쭉 내리면서 읽는다. 폰을 세워 들고 볼 때 편하다.

읽던 위치는 스크롤에서도 그대로 기억된다.

# 사용법 3 — GitHub 저장소에서 읽기

인터넷만 되면 어느 기기에서든 같은 만화를 읽고 싶을 때 쓴다.
만화를 **비공개** 저장소에 올려두고, 앱에서 그 저장소를 연결한다.

## 1. 저장소를 만든다

GitHub에 **비공개(Private)** 저장소를 하나 만들고, 위에서 설명한 폴더 구조 그대로 올린다.
목록을 만들거나 설정 파일을 두는 일은 필요 없다 — 폴더만 올리면 된다.

## 2. 토큰을 발급한다

GitHub → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**

- **Repository access** — Only select repositories → 방금 만든 저장소 하나만
- **Permissions → Repository permissions → Contents** → **Read-only**

그 외 권한은 주지 않는다. 이 토큰으로 할 수 있는 일은 그 저장소 하나를 읽는 것뿐이다.

## 3. 연결한다

**뷰어 → GitHub 저장소 → 토큰 붙여넣기 → 연결.** 그게 전부다.

소유자도 저장소 이름도 묻지 않는다. **토큰이 어느 저장소를 읽을 수 있는지 앱이 물어보기 때문이다.**
접근할 수 있는 저장소가 하나면 바로 연결되고, 여럿이면 목록에서 고르면 된다.

연결하면 **무엇을 찾았는지 말해준다** — `코미 양은, 커뮤증이에요 · 252화를 찾았어요`.
엉뚱한 저장소를 골랐다면 여기서 바로 드러난다. 앱 소스가 든 저장소를 고르면
`icons · 1화` 같은 게 뜬다.

| 버튼 | |
|---|---|
| **목록 새로고침** | 회차를 새로 올린 뒤 누른다 |
| **다른 저장소** | 토큰과 받아둔 페이지는 그대로 두고 저장소만 바꾼다 |
| **연결 해제 · 캐시 삭제** | 토큰과 내려받은 페이지를 모두 지운다 |

> **찾는 저장소가 목록에 없다면** 토큰에 그 저장소가 포함되지 않은 것이다.
> [토큰 설정](https://github.com/settings/personal-access-tokens)에서 **Repository access**에 추가하면 된다.
> 목록을 거치지 않고 **주소 직접 넣기**로 가도 되는데, `사용자명/저장소` 든
> `https://github.com/사용자명/저장소` 든 붙여넣으면 알아본다.

## 알아둘 것

**토큰은 이 기기의 브라우저 저장소에만 남는다.** GitHub 외에는 어디로도 전송되지 않는다.
다만 브라우저에 남는 자격 증명이라는 점은 감안해야 한다 — 공용 컴퓨터에서는 다 읽고 나서 연결을 해제할 것.

**한 번 본 페이지는 다시 받지 않는다.** 내용 해시로 캐시하므로 같은 페이지를 두 번 내려받는 일이 없고,
앱이 업데이트돼도 캐시는 지워지지 않는다.

**저장소가 아주 크면** 목록을 한 번에 못 받을 수 있다. 그때는 시리즈를 저장소 여러 개로 나눈다.

**연결이 안 되면 이유를 말한다.** GitHub은 토큰이 못 보는 저장소도 "없음"으로 답하기 때문에
(있는지 없는지 떠보지 못하게 하려고) 이름이 틀린 것과 권한이 없는 것이 똑같이 보인다.
그래서 앱이 토큰의 주인을 한 번 더 물어 둘을 갈라준다.

- 토큰이 아예 거부됨 → 다시 발급하라고
- 토큰은 멀쩡한데 그 저장소가 안 보임 → **Repository access**와 **Contents**를 확인하라고
- 토큰 주인이 다른 계정 → 누구 것인지 밝히면서
- 이름이 틀림 → 소유자·저장소 이름을 확인하라고

**폴더 구조는 로컬과 같다.** 잘라둔 낱장이면 `시리즈/화/페이지`, 자르지 않은 긴 캡처면
`시리즈/001화.png`. 하위 경로로 시리즈 폴더 하나를 지정해도 그 폴더의 이름은 유지된다.

## 잘 안 될 때

| 증상 | 원인과 대처 |
|---|---|
| 페이지 선이 전부 엉뚱하다 | 좌우 여백이 잘못 잡혔을 가능성이 높다. **만화 영역**의 왼쪽·오른쪽을 확인한다. 판형 비율은 *페이지 폭*에 곱해지므로 폭이 틀리면 전부 틀어진다 |
| 페이지가 두 배 크기로 잘린다 | 두 페이지 펼침으로 잘못 판단했거나 그 반대다. **페이지 수**를 두 배로 하거나 절반으로 해본다 |
| "이미지가 너무 커서 분석할 수 없어요" | 캡처를 몇 개로 나눠서 올린다 |
| 컬러 표지가 통째로 잘려 안 보인다 | 고쳐졌다. 광고는 색이 아니라 **띠의 두께**로 가려낸다 — 페이지 폭의 절반보다 얇은 컬러 띠만 광고로 본다. 그래도 잘리면 **만화 영역**의 `위` 값을 줄인다 |
| 낱장 저장이 중간에 멈춘다 | 브라우저가 여러 파일 다운로드를 막고 있다. 주소창의 알림에서 허용한다 |
| 폴더를 골랐는데 아무것도 안 나온다 | 폴더 안에 이미지 파일이 있는지 확인한다. `.png .jpg .jpeg .webp .gif .avif .bmp`만 읽는다 |
| 긴 캡처인데 안 잘리고 통째로 나온다 | 세로가 가로의 2.2배는 넘어야 캡처로 본다. 그보다 짧으면 한 장짜리 페이지로 취급한다. 이럴 땐 편집에서 직접 자른다 |
| 잘린 위치가 마음에 안 든다 | 읽으면서 **설정 → 페이지 수**의 `−` `+`로 조절한다. 이 화에만 적용되고 기억된다. 더 정밀하게 고치려면 편집에서 경계를 직접 찍는다 |
| 화 순서가 뒤죽박죽이다 | 폴더 이름에 숫자를 넣는다 (`001화`, `1화`, `ch01` 모두 인식한다) |
| 두 쪽 보기에서 짝이 어긋난다 | **표지 단독 / 나란히**를 눌러 바꾼다 |
| 표지에서 다음 장으로 갈 때만 모션이 없다 | 한 장에서 두 장으로 바뀌는 순간은 종이 크기가 정해지지 않아 일부러 건너뛴다 |
| 넘기는 모션이 무겁다 | **설정 → 넘기는 모션**을 끈다. 시스템의 "동작 줄이기"를 켜두면 자동으로 꺼진다 |
| 이어서 읽기를 눌렀는데 폴더를 다시 고르란다 | 브라우저가 폴더 권한을 기억하지 못한다. 데스크톱 Chrome/Edge에서는 바로 이어진다 |
| 연결은 됐는데 만화가 없다 | 저장소를 잘못 골랐을 수 있다. 연결 직후 뜨는 안내가 무엇을 찾았는지 말해준다 — 앱 소스 저장소를 고르면 `icons`가 뜬다. **다른 저장소**로 바꾸면 된다 |
| 목록에 원하는 저장소가 없다 | 토큰 권한에 그 저장소가 안 들어 있다. [토큰 설정](https://github.com/settings/personal-access-tokens)의 **Repository access**에 추가하고 다시 연결한다 |
| 저장소 연결이 안 된다 | 화면이 이유를 말해준다 — 토큰이 거부됐는지, 토큰은 멀쩡한데 그 저장소가 권한에 안 들어 있는지, 이름이 틀렸는지 구분해서 알려준다 |

# 만드는 쪽 이야기

## 어떻게 페이지를 찾는가

여백을 하나하나 찾아 헤매는 대신, **판형이라는 고정된 기준**에서 출발한다.

1. **페이지 폭 측정** — 잉크가 있는 첫 열~마지막 열이 아니라, *밀도가 높은 가장 넓은 연속 구간*을 찾는다.
   페이지는 전체 높이에 걸쳐 내용이 있지만, 페이지 밖에 떠 있는 사이트 버튼은 몇 줄뿐이라 걸러진다.
2. **판형 후보 대보기** — 스캔이 한 페이지인지 두 페이지 펼침인지 모르므로,
   `폭 × 비율`과 `(폭/2) × 비율`을 모두 그리드로 놓아보고 **경계선이 실제 여백에 떨어지는지 채점**해 고른다.
   여백의 *두께*를 함께 보기 때문에 컷 사이 얇은 틈과 페이지 사이 두꺼운 여백을 구분한다.
3. **여백에 스냅** — 스트립은 `페이지-여백-페이지-여백…` 구조라 전체를 균등 분할하면
   구조적으로 ±여백/2 만큼 어긋난다(양 끝에서 최대). 그래서 그리드는 위치만 정하고,
   각 선을 실제 여백 한가운데로 붙인다. 다음 선은 앞 선이 *실제로 놓인 자리*에서 재계산해
   페이지 높이가 들쭉날쭉해도 오차가 누적되지 않는다.

판단은 `core/layout.js`에 한 벌만 있고 편집과 뷰어가 같이 쓴다. 뷰어에서 자른 결과가
편집에서 자른 결과와 반드시 같아야 하므로, 복사가 아니라 공유여야 한다.

## 종이는 어떻게 넘어가는가

평면을 회전시키는 방식이 흔하지만, 그러면 여닫이문처럼 보인다. **종이는 휘고, 늘어나지 않는다.**
책등에서 바깥 끝까지의 길이가 넘기는 내내 같으므로, 자유단은 뻣뻣한 판이 갈 수 있는 만큼
멀리 가지 못한다. 이걸 틀리면 이유는 몰라도 어색하다는 것은 바로 눈에 띈다.

그래서 시트를 **일정 곡률의 호**로 모델링한다. 호 길이가 구조적으로 보존되고 닫힌 형태가 있어
매 프레임 이백 개의 열을 계산해도 부담이 없다.

```
a(s) = θ + κs                    호 길이 s 지점의 접선 각도
x(s) = [sin a(s) − sin θ] / κ    페이지를 따라
z(s) = [cos θ − cos a(s)] / κ    읽는 사람 쪽으로
```

그리기는 얇은 세로 슬라이스의 나열이다. 브라우저가 빨리 그릴 수 있는 것은 축에 나란한
사각형뿐이라, 곡면은 각각은 곧은 사각형 이백 개가 된다. 나머지는 전부 그 대가다.

- 슬라이스는 1px씩 겹친다. 안 그러면 반올림 틈이 생겨 빗처럼 보인다
- 겹치므로 **음영을 슬라이스마다 칠할 수 없다** — 반투명을 두 번 칠한 이음매가 어두워져
  줄무늬가 된다. 빛은 나중에 그라디언트 하나로, 종이 실루엣에 클립해서 올린다
- 거의 옆으로 누우면 페이지 전체가 좁은 띠로 눌리므로, 실제 차지하는 화면 폭에 맞춰
  슬라이스 수를 줄인다
- 들린 종이는 **작게** 그린다. 크게 그리는 편이 물리적으로는 맞지만 캔버스가 책과 같은
  크기라 위아래가 잘린다

끌어서 넘길 때는 접힌 자리가 손끝을 따라온다. 놓으면 속도가 위치보다 우선한다 —
살짝만 움직였어도 빠르게 튕겼다면 넘길 뜻이었던 것이다.

## 만화는 어디서 오는가

뷰어는 페이지가 어디서 왔는지 모른다. 무엇이든 **페이지 공급원** 하나로 감싸서 건네받는다
(`몇 장인지`, `i번째 페이지를 다오`, `다음 화가 있는가`). 그래서 같은 뷰어가 네 가지를 다 읽는다.

- **방금 자른 스트립** — 원본 캔버스에서 해당 구간을 잘라 그린다
- **로컬 폴더의 낱장** — 파일을 하나씩 디코딩한다
- **로컬 폴더의 긴 캡처** — 열 때 한 번 재어 사각형 목록만 남기고, 그릴 때 다시 연다
- **GitHub 비공개 저장소** — 토큰으로 받아온다

캐시 전략이 둘로 갈리는 이유가 여기 있다. 낱장은 파일 하나가 페이지 하나라 **페이지 기준**으로
읽는 자리 주변만 남긴다. 긴 캡처는 파일 하나가 페이지 수십 장이고 디코딩하면 수십 MB라
**파일 기준**으로 두 개까지만 쥔다. 앞으로 읽으면 한 파일이 수십 장을 연달아 대주므로 그걸로 충분하다.

## 구조

```
index.html              PWA 진입점 — 처음 화면 / 편집 / 뷰어 / 읽기
src/
  styles.css
  main.js               부트스트랩 + 서비스 워커 등록
  core/                 순수 로직 — DOM 없음, 단위 테스트 대상
    analysis.js         행/열 통계 (밝기, 분산, 채도, 잉크 밀도)
    geometry.js         영역 검출, 여백 지도, 판형 맞춤, 페이지 계산
    bookmarks.js        핀 저장소 — 담기, 빼기, 시리즈별 묶기
    curl.js             넘어가는 종이의 형태 — 호 길이 보존, 명암, 관성
    layout.js           편집과 뷰어가 함께 쓰는 판단 — 영역과 페이지 결정
    naming.js           경로를 시리즈/화/페이지로 묶기, 자연 정렬
    pdf.js              JPEG를 /DCTDecode로 박아넣는 최소 PDF 라이터
  ui/
    app.js              셸 — 화면 전환, 뷰어 소유, 토스트
    editor.js           편집 — 업로드, 컨트롤, 미리보기, 내보내기
    reader.js           읽기 — 배치, 넘김 모션, 화 넘어가기
    sources.js          페이지 공급원 + 디코딩 창(window)
    slicer.js           긴 캡처를 뷰어에서 잘라내기
    curl.js             종이를 캔버스에 그리기 — 슬라이스, 실루엣, 그림자
    library.js          만화 고르기 — 폴더 3단 대응, 시리즈/화 탐색
    github.js           비공개 저장소 — 토큰, 트리 조회, SHA 캐시
scripts/build-artifact.mjs   모듈을 단일 HTML로 인라인 (Claude Artifact용)
tests/
  fixtures.mjs          합성 스트립 생성기 (이미지 라이브러리 불필요)
  core.test.mjs         순수 로직 단위 테스트
  bookmarks.test.mjs    핀 저장소 단위 테스트
  curl.test.mjs         종이 형태 단위 테스트
  layout.test.mjs       영역·페이지 판단 단위 테스트
  naming.test.mjs       경로 묶기 단위 테스트
  e2e.spec.mjs          Playwright 브라우저 테스트
```

핵심은 `src/core/`에 몰려 있고 브라우저 없이 테스트된다. `src/ui/`가 DOM을 담당한다.

## 개발

```bash
npm install
npm run dev        # http://localhost:8080
npm test           # 단위 테스트
npm run test:e2e   # 브라우저 테스트
npm run build      # dist/artifact.html (단일 파일)
```

빌드는 두 갈래다. **PWA**는 `index.html`이 ES 모듈을 그대로 불러오고 GitHub Pages로 배포된다.
**단일 파일**은 Claude Artifact용이라 전부 인라인되며, 외부 요청이 막혀 있어 GitHub 저장소 기능이 나타나지 않는다.
UI를 고쳤으면 두 경로 모두 확인할 것.

## 배포

`main`에 푸시하면 GitHub Actions가 GitHub Pages로 배포한다.
저장소 **Settings → Pages → Source**를 **GitHub Actions**로 설정해두면 된다.
