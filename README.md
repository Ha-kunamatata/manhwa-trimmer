# 만화 재단기 (Manhwa Trimmer)

만화를 **자르고**, 만화책처럼 **읽는** 도구.

### → [ha-kunamatata.github.io/manhwa-trimmer](https://ha-kunamatata.github.io/manhwa-trimmer/)

설치할 것도, 로그인할 것도 없다. 브라우저 안에서만 동작하며 **이미지는 어디로도 전송되지 않는다.**

---

## 무엇을 하는 도구인가

열면 두 갈래로 나뉜다.

| | |
|---|---|
| **편집** | 길게 캡처한 세로로 긴 이미지를 만화책 판형에 맞춰 낱장으로 자른다 |
| **뷰어** | 이미 잘라둔 만화를 진짜 만화책처럼 읽는다 |

보통은 **편집으로 한 번 자르고 → 저장 → 그 폴더를 뷰어로 읽는** 흐름이 된다.

---

# 사용법 1 — 편집 (자르기)

## 1. 이미지 올리기

처음 화면에서 **편집**을 누르고, 긴 캡처 이미지를 끌어다 놓거나 클릭해서 고른다.
PNG · JPG · WebP를 받는다. 한 번에 한 장씩 처리한다.

올리면 바로 분석이 시작된다. 큰 이미지는 몇 초 걸린다.

## 2. 알아서 잡은 것을 확인한다

분석이 끝나면 미리보기에 두 가지가 겹쳐 그려진다.

- **빗금 친 바깥 영역** — 잘라낼 사이트 UI (상하단 광고 배너, 좌우 여백)
- **가로선** — 페이지가 나뉘는 자리

왼쪽 패널에는 판단 근거가 적힌다. 예를 들면

> 한 페이지 배치로 판단했어요. 페이지 폭 580px × 1.414 → 9장, 경계 정확도 94%.

**대부분 여기서 끝난다.** 선이 여백 한가운데에 잘 떨어져 있으면 그냥 저장하면 된다.

## 3. 어긋났으면 손으로 고친다

| 증상 | 이렇게 한다 |
|---|---|
| 선 하나가 없거나 남는다 | 미리보기에서 **그 자리를 클릭**한다. 빈 곳을 누르면 선이 생기고, 기존 선 근처를 누르면 지워진다. 새 선은 가까운 여백 한가운데로 알아서 붙는다 |
| 전체가 한 장씩 밀렸다 | **페이지 수**를 ±1 한다 |
| 전체가 조금씩 위아래로 어긋난다 | **시작 보정**(px)을 조절한다. 첫 페이지가 시작하는 위치를 밀거나 당긴다 |
| 판형을 잘못 잡았다 | **만화책 판형**을 직접 고른다. 단행본(1:1.414) · 신서판(1:1.5) · 와이드판(1:1.3), 또는 비율 직접 입력 |
| 광고 배너가 덜 잘렸다 | **만화 영역**의 위/아래/왼쪽/오른쪽 값을 직접 고친다. **자동 재감지**로 되돌릴 수 있다 |

손으로 고친 게 있으면 **수동 편집 초기화** 버튼이 나타난다. 자동 판단으로 되돌리고 싶을 때 누른다.

> **판형을 직접 고르면 자동 맞춤이 꺼진다.** 자동이 잘 맞고 있다면 건드리지 않는 편이 낫다 —
> 자동은 후보를 실제 이미지에 대보고 채점해서 고르는 반면, 직접 고른 비율은 그냥 그 값으로 균등 분할한다.

## 4. 저장한다

세 가지 길이 있다.

**PDF 한 파일로 저장** (권장) — 전체가 한 파일로 나온다. 폰·태블릿의 아무 PDF 뷰어에서나 열린다.
용량이 크면 화질을 단계적으로 낮춰가며 자동으로 맞춘다.

**낱장 이미지로 저장** — 페이지마다 `이름_01.png`, `이름_02.png` … 로 나온다.
**뷰어로 다시 읽으려면 이쪽이다.** 브라우저가 "여러 파일 다운로드를 허용할까요?"라고 물으면 허용한다.

**개별 페이지 저장** — 페이지 카드의 ⤓ 아이콘. 한 장만 필요할 때.

파일 이름과 화질은 **내보내기** 패널에서 정한다. **고화질 PNG**를 끄면 JPEG로 나와 용량이 크게 준다.

**만화책으로 읽기**를 누르면 저장하지 않고 바로 읽어볼 수도 있다. 잘린 결과를 확인하는 데 좋다.

# 사용법 2 — 뷰어 (읽기)

## 1. 폴더를 이렇게 만들어 둔다

뷰어는 폴더 이름으로 시리즈와 화를 알아본다. 규칙은 하나다 —
**페이지가 든 폴더가 화, 그 위 폴더가 시리즈.**

```
만화/                     ← 이 폴더를 고른다
  원피스/                 ← 시리즈
    001화/                ← 화
      p01.png             ← 페이지
      p02.png
    002화/
      p01.png
  나루토/
    001화/
      p01.png
```

폴더를 하나만 골라도 된다. 어느 층을 골라도 같은 규칙으로 읽는다.

| 고른 것 | 결과 |
|---|---|
| `만화/` | 시리즈 여러 개, 각각 화 여러 개 |
| `원피스/` | 시리즈 하나(원피스), 화 여러 개 |
| `001화/` | 화 하나 |

**파일 이름은 사람이 읽는 순서대로 정렬된다.** `9화`가 `10화`보다 앞에 오고,
`p2.png`가 `p10.png`보다 앞에 온다. 자릿수를 맞춰 `p01`, `p02`로 두면 더 확실하다.

## 2. 폴더를 고른다

**뷰어 → 폴더 선택.**

브라우저마다 사정이 다르다.

| | |
|---|---|
| **데스크톱 Chrome / Edge** | 폴더를 고르면 권한이 남는다. 다음에 열 때 **‹폴더이름› 다시 열기** 버튼 한 번이면 된다 |
| 그 외 데스크톱 브라우저 | 폴더를 고를 수는 있지만 매번 다시 골라야 한다 |
| **iOS Safari** | 폴더 선택 자체가 없다. **이미지 여러 개 선택**을 쓴다 (한 화씩 읽게 된다) |

## 3. 읽는다

시리즈 카드를 누르면 화 목록이 나오고, 화를 누르면 읽기가 시작된다.

- **한 화가 끝나면 다음 화로 이어진다.** 마지막 쪽에서 한 번 더 넘기면 된다
- **읽던 자리를 기억한다.** 시리즈 카드에 `이어보기 · 003화 12쪽`이 붙고, 그 화를 누르면 그 자리에서 시작한다
- 기억은 이 기기의 브라우저에만 남는다 (기기 간 동기화는 아직 없다)

## 읽기 화면 조작

### 마우스 · 손가락

| | |
|---|---|
| 화면 좌우 끝을 누른다 | 페이지를 넘긴다 |
| 좌우로 민다 | 페이지를 넘긴다 |

오른쪽→왼쪽으로 읽는 중이면 **왼쪽을 눌러야 다음 장**이다. 종이 만화책과 같다.

### 키보드

| | |
|---|---|
| `←` `→` | 페이지 넘기기 (읽는 방향에 따름) |
| `Space` / `PageDown` | 다음 |
| `PageUp` | 이전 |
| `D` | 한 쪽 / 두 쪽 전환 |
| `Home` / `End` | 처음 / 끝 |
| `Esc` | 닫기 |

### 위쪽 버튼

| | |
|---|---|
| **한 쪽 / 두 쪽** | 낱장으로 볼지, 책처럼 펼쳐 볼지. 처음엔 화면 크기를 보고 알아서 정한다 |
| **표지 단독 / 나란히** | 첫 장을 표지로 혼자 둘지 여부. 실제 책처럼 표지 한 장 뒤부터 짝을 이룬다. 짝이 어긋나 보이면 이걸 누른다 |
| **오른쪽 → 왼쪽** | 읽는 방향. 일본·한국 만화는 오른쪽→왼쪽, 서양 만화는 왼쪽→오른쪽 |
| **화면 맞춤 / 폭 맞춤** | 한 화면에 다 넣을지, 가로를 꽉 채우고 세로로 스크롤할지 |
| **넘김 켜짐 / 꺼짐** | 책장 넘어가는 모션. 끄면 즉시 바뀐다 |

설정은 기억되므로 매번 다시 맞출 필요가 없다.

> 두 쪽 보기에서 넘기면 종이 한 장이 책등을 축으로 돌아간다. 들리는 쪽 아래로 다음 장이 드러나고,
> 반대쪽은 종이가 내려앉을 때까지 이전 장을 유지한다. 시스템에서 "동작 줄이기"를 켜두었다면 자동으로 꺼진다.

# 사용법 3 — GitHub 저장소에서 읽기

인터넷만 되면 어느 기기에서든 같은 만화를 읽고 싶을 때 쓴다.
만화를 **비공개** 저장소에 올려두고, 앱에서 그 저장소를 연결한다.

## 1. 저장소를 만든다

GitHub에 **비공개(Private)** 저장소를 하나 만들고, 위에서 설명한 폴더 구조 그대로 올린다.
목록을 만들거나 설정 파일을 두는 일은 필요 없다 — 폴더만 올리면 된다.

## 2. 토큰을 발급한다

GitHub → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**

- **Repository access** — Only select repositories → 방금 만든 저장소 하나만
- **Permissions → Repository permissions → Contents** → **Read-only**

그 외 권한은 주지 않는다. 이 토큰으로 할 수 있는 일은 그 저장소 하나를 읽는 것뿐이다.

## 3. 연결한다

**뷰어 → GitHub 저장소**를 누르고 채운다.

| | |
|---|---|
| 소유자 | GitHub 사용자명 |
| 저장소 | 저장소 이름 |
| 브랜치 | 비워두면 기본 브랜치 |
| 하위 경로 | 저장소 안 특정 폴더만 쓸 때. 비워두면 전체 |
| 액세스 토큰 | 위에서 발급한 것 |

한 번 연결하면 다음부터는 **목록 새로고침**만 누르면 된다.
**연결 해제 · 캐시 삭제**로 토큰과 내려받은 페이지를 지울 수 있다.

## 알아둘 것

**토큰은 이 기기의 브라우저 저장소에만 남는다.** GitHub 외에는 어디로도 전송되지 않는다.
다만 브라우저에 남는 자격 증명이라는 점은 감안해야 한다 — 공용 컴퓨터에서는 다 읽고 나서 연결을 해제할 것.

**한 번 본 페이지는 다시 받지 않는다.** 내용 해시로 캐시하므로 같은 페이지를 두 번 내려받는 일이 없고,
앱이 업데이트돼도 캐시는 지워지지 않는다.

**저장소가 아주 크면** 목록을 한 번에 못 받을 수 있다. 그때는 **하위 경로**로 범위를 좁힌다.

## 폰에 설치하기

주소를 폰 브라우저로 연 뒤

- **iOS Safari** — 공유 → 홈 화면에 추가
- **Android Chrome** — 메뉴 → 앱 설치

설치하면 앱처럼 열리고, 오프라인에서도 동작한다 (로컬 파일 기준. 저장소에서 읽으려면 인터넷이 필요하다).

## 잘 안 될 때

| 증상 | 원인과 대처 |
|---|---|
| 페이지 선이 전부 엉뚱하다 | 좌우 여백이 잘못 잡혔을 가능성이 높다. **만화 영역**의 왼쪽·오른쪽을 확인한다. 판형 비율은 *페이지 폭*에 곱해지므로 폭이 틀리면 전부 틀어진다 |
| 페이지가 두 배 크기로 잘린다 | 두 페이지 펼침으로 잘못 판단했거나 그 반대다. **페이지 수**를 두 배로 하거나 절반으로 해본다 |
| "이미지가 너무 커서 분석할 수 없어요" | 캡처를 몇 개로 나눠서 올린다 |
| 낱장 저장이 중간에 멈춘다 | 브라우저가 여러 파일 다운로드를 막고 있다. 주소창의 알림에서 허용한다 |
| 폴더를 골랐는데 아무것도 안 나온다 | 폴더 안에 이미지 파일이 있는지 확인한다. `.png .jpg .jpeg .webp .gif .avif .bmp`만 읽는다 |
| 화 순서가 뒤죽박죽이다 | 폴더 이름에 숫자를 넣는다 (`001화`, `1화`, `ch01` 모두 인식한다) |
| 두 쪽 보기에서 짝이 어긋난다 | **표지 단독 / 나란히**를 눌러 바꾼다 |
| 저장소 연결이 안 된다 | 토큰 권한이 **Contents: Read-only**인지, 그 저장소가 **Only select repositories**에 포함됐는지 확인한다 |

## 개인정보

- 이미지는 **기기 밖으로 나가지 않는다.** 서버가 없고, 업로드하는 곳도 없다
- 설정과 읽던 위치는 브라우저 저장소에만 남는다
- GitHub 저장소를 연결한 경우에만 GitHub와 통신한다

# 만드는 쪽 이야기

## 어떻게 페이지를 찾는가

여백을 하나하나 찾아 헤매는 대신, **판형이라는 고정된 기준**에서 출발한다.

1. **페이지 폭 측정** — 잉크가 있는 첫 열~마지막 열이 아니라, *밀도가 높은 가장 넓은 연속 구간*을 찾는다.
   페이지는 전체 높이에 걸쳐 내용이 있지만, 페이지 밖에 떠 있는 사이트 버튼은 몇 줄뿐이라 걸러진다.
2. **판형 후보 대보기** — 스캔이 한 페이지인지 두 페이지 펼침인지 모르므로,
   `폭 × 비율`과 `(폭/2) × 비율`을 모두 그리드로 놓아보고 **경계선이 실제 여백에 떨어지는지 채점**해 고른다.
   여백의 *두께*를 함께 보기 때문에 컷 사이 얇은 틈과 페이지 사이 두꺼운 여백을 구분한다.
3. **여백에 스냅** — 스트립은 `페이지-여백-페이지-여백…` 구조라 전체를 균등 분할하면
   구조적으로 ±여백/2 만큼 어긋난다(양 끝에서 최대). 그래서 그리드는 위치만 정하고,
   각 선을 실제 여백 한가운데로 붙인다. 다음 선은 앞 선이 *실제로 놓인 자리*에서 재계산해
   페이지 높이가 들쭉날쭉해도 오차가 누적되지 않는다.

## 만화는 어디서 오는가

뷰어는 페이지가 어디서 왔는지 모른다. 무엇이든 **페이지 공급원** 하나로 감싸서 건네받는다
(`몇 장인지`, `i번째 페이지를 다오`, `다음 화가 있는가`). 그래서 같은 뷰어가 세 가지를 다 읽는다.

- **방금 자른 스트립** — 원본 캔버스에서 해당 구간을 잘라 그린다
- **로컬 폴더** — 파일을 하나씩 디코딩한다
- **GitHub 비공개 저장소** — 토큰으로 받아온다

수백 장을 한꺼번에 디코딩하면 폰의 메모리가 먼저 죽으므로, 읽고 있는 페이지 주변만 남기고
나머지는 놓아준다.

## 구조

```
index.html              PWA 진입점 — 처음 화면 / 편집 / 뷰어 / 읽기
src/
  styles.css
  main.js               부트스트랩 + 서비스 워커 등록
  core/                 순수 로직 — DOM 없음, 단위 테스트 대상
    analysis.js         행/열 통계 (밝기, 분산, 채도, 잉크 밀도)
    geometry.js         영역 검출, 여백 지도, 판형 맞춤, 페이지 계산
    naming.js           경로를 시리즈/화/페이지로 묶기, 자연 정렬
    pdf.js              JPEG를 /DCTDecode로 박아넣는 최소 PDF 라이터
  ui/
    app.js              셸 — 화면 전환, 뷰어 소유, 토스트
    editor.js           편집 — 업로드, 컨트롤, 미리보기, 내보내기
    reader.js           읽기 — 배치, 넘김 모션, 화 넘어가기
    sources.js          페이지 공급원 + 디코딩 창(window)
    library.js          만화 고르기 — 폴더 3단 대응, 시리즈/화 탐색
    github.js           비공개 저장소 — 토큰, 트리 조회, SHA 캐시
scripts/build-artifact.mjs   모듈을 단일 HTML로 인라인 (Claude Artifact용)
tests/
  fixtures.mjs          합성 스트립 생성기 (이미지 라이브러리 불필요)
  core.test.mjs         순수 로직 단위 테스트
  naming.test.mjs       경로 묶기 단위 테스트
  e2e.spec.mjs          Playwright 브라우저 테스트
```

핵심은 `src/core/`에 몰려 있고 브라우저 없이 테스트된다. `src/ui/`가 DOM을 담당한다.

## 개발

```bash
npm install
npm run dev        # http://localhost:8080
npm test           # 단위 테스트
npm run test:e2e   # 브라우저 테스트
npm run build      # dist/artifact.html (단일 파일)
```

빌드는 두 갈래다. **PWA**는 `index.html`이 ES 모듈을 그대로 불러오고 GitHub Pages로 배포된다.
**단일 파일**은 Claude Artifact용이라 전부 인라인되며, 외부 요청이 막혀 있어 GitHub 저장소 기능이 나타나지 않는다.
UI를 고쳤으면 두 경로 모두 확인할 것.

## 배포

`main`에 푸시하면 GitHub Actions가 GitHub Pages로 배포한다.
저장소 **Settings → Pages → Source**를 **GitHub Actions**로 설정해두면 된다.
